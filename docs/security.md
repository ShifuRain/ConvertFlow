# Security overview

This is a summary of the threat model and of what ConvertFlow does and does not protect. The Grundschutz view is in [grundschutz-mapping.md](grundschutz-mapping.md); the deployment view is in [operations.md](operations.md). To report a vulnerability, see [SECURITY.md](../SECURITY.md).

## Deployment assumption

ConvertFlow is designed for an isolated (air-gapped) network segment with a trusted, or at least organizationally controlled, set of users. It has **no authentication and no authorization**, by explicit operator decision. Everything a reachable client can do is available to every reachable client.

## Assets

| Asset | Where | Notes |
|---|---|---|
| Uploaded media (inputs) | `media` volume, `/data/in/<uuid>` | removed after the job finishes, on delete, and by the orphan sweep |
| Converted media (outputs) | `media` volume, `/data/out/<uuid>.<attempt>.<ext>` | kept for `CONVERTFLOW_RETENTION` (24 h default) |
| Job metadata | PostgreSQL | filename (sanitized), options, probe summary, error text, timestamps |
| Availability of CPU, memory and disk | host | the main thing an anonymous client can consume |
| Database credentials | `./secrets` on the host, mounted as `/run/secrets/*` | never placed in environment variables; api and worker receive only the URL of the unprivileged role `convertflow_app` |
| Object store (S3 storage only) | the bucket: `in/<uuid>`, `out/<uuid>.<attempt>.<ext>`; api and worker keys as file secrets | inputs, outputs and their retention as above; see [on-demand.md](on-demand.md) |

## Actors and threats

| Threat | Mitigation in the product | Remaining exposure |
|---|---|---|
| **Hostile media file** exploiting a decoder (FFmpeg/libraries) | Parsing happens only in the `worker` container: non-root (uid 65532), read-only root filesystem, all capabilities dropped, `no-new-privileges`, default seccomp, pids/memory/CPU limits, no network egress (internal `backend` network), no host mounts besides the `media` volume and secrets. The API image contains no FFmpeg and no media decoder. Inputs are probed with ffprobe first and limited by duration, pixel count and stream count; output size is capped. | A memory-safety bug in FFmpeg or a codec library could still execute code inside the worker container with its privileges: read/write access to the `media` volume (other users' files in retention) and to the database credentials of the application role `convertflow_app` (not a superuser; it can read and change all job rows). Container escape protection depends on the runtime and kernel. FFmpeg 7.1.1 is pinned; update it on security advisories. |
| **FFmpeg used as a file reader / SSRF** (playlists, concat, network protocols, `file:` references in container formats) | FFmpeg is built with `--disable-network`; the command line sets `-protocol_whitelist file` and `-format_whitelist` with the supported container formats only (playlist demuxers such as HLS/concat are not on the list). Tests: `internal/ffmpeg/whitelist_test.go`, `internal/e2e/hostile_test.go` (`TestPlaylistAndConcatInputsRejected`, `TestPlaylistInputsLeaveNoTraces`). | Defense in depth, not a proof. |
| **Command / argument injection** | No shell is involved. `ffmpeg.BuildArgs` is the only place command lines are built; user input is limited to a preset id and four validated numeric options (fixed lists/ranges). Paths are server-generated UUIDs. Tests: `internal/ffmpeg/args_test.go`, `internal/jobs/options_test.go`. | |
| **Path traversal / hostile filenames** | The client filename is never used as a path; it is sanitized (no path components, control or bidi characters, quotes) and used for display and the `Content-Disposition` header only. The delete paths refuse to remove anything outside the data directory. Tests: `TestUploadHostileFilenameStaysInsideDataDir`, `TestSanitizeFilenameHostile`, `TestContentDispositionSafe`, `TestHostileFilenamesEndToEnd`. | |
| **Decompression bombs / oversized input** | Upload size limit (8 GiB default), duration/pixel/stream limits checked after probing, output cap with `-fs`, per-run timeout (4 h default), free-space check before accepting an upload. Test: `TestDecompressionBombsRefused`. | Limits are generous by default. Tune them to the hardware ([operations.md](operations.md#configuration-reference)). |
| **Denial of service by an anonymous client** | Caps on concurrent uploads (4), active jobs (100), SSE streams (64); rolling idle limit for uploads (60 s); header read timeout (10 s); `503`/`507` with `Retry-After`; resource limits per container. | A client that can reach the service can still fill the queue and the disk up to the configured caps and occupy the CPU for the duration of the queue. No per-client rate limiting exists (there is no client identity). Use network-level controls. |
| **Reading or deleting other users' jobs** | None. Job ids are random UUIDs, but `GET /api/v1/jobs` lists the latest 200 jobs with their ids, filenames and status, and `DELETE` needs no credential. | Accepted risk; see [risk-acceptance-template.md](risk-acceptance-template.md). |
| **Web attacks against the UI** (XSS, clickjacking, MIME sniffing) | CSP `default-src 'none'; script-src 'self'; style-src 'self'; ...; frame-ancestors 'none'` (no inline script or style), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`, `Cache-Control: no-store` on `/api/`, HSTS when TLS is terminated by the application. No cookies or sessions. All UI assets are embedded; no external requests. Tests: `TestSecurityHeaders`, `TestSecurityHeadersOnProblemAndAPI`, `TestSecurityHeadersIncludeCOOP`, `internal/ui/ui_test.go`. | |
| **DNS rebinding**: a malicious page makes the operator's browser resolve its domain to `127.0.0.1` or a LAN address, so that the page becomes "same-origin" with the unauthenticated service and can read job lists, filenames and downloads. | Secure default: every route (API, SSE, downloads, UI, `/healthz`, `/metrics`) answers `421` problem+json unless the `Host` header is `localhost` or an IP literal, or is listed in `CONVERTFLOW_ALLOWED_HOSTS` (hostnames compared case-insensitively, userinfo/whitespace/malformed values refused, `*` disables). Refusals are audited as `request_rejected` / `host_not_allowed` without the offending value. Tests: `TestHostGuardTableAllRoutes` (`internal/api`), `TestRebindingHostRefusedOnEveryRoute` (`internal/e2e`), `internal/hostcheck`. | Operators using a DNS name or a reverse proxy **must** set `CONVERTFLOW_ALLOWED_HOSTS` ([operations.md](operations.md#dns-rebinding-host-allow-list)), otherwise the service answers `421`. Setting `*` removes the protection. Non-browser clients are unaffected by design. Not verified in a real browser. |
| **Cross-origin requests from a browser (CSRF-like)**: a web page open in an operator's browser submits an upload or a `DELETE` to `http://127.0.0.1:8080` or to the internal host name. Because there is no authentication, such a request would otherwise be accepted. | All state-changing methods (`POST`, `PUT`, `PATCH`, `DELETE`) under `/api/` are refused with `403` before the body is read when `Sec-Fetch-Site` is present and not `same-origin`/`none`, or, if that header is absent, when `Origin` is present and its host:port differs from `Host` (scheme-insensitive; `Origin: null` is refused; `X-Forwarded-Host` is not trusted). Refusals are audited as `request_rejected` / `cross_origin` without client-supplied strings. `GET` handlers never change state. Tests: `TestCrossOriginTable`, `TestCrossOriginAuditIsGeneric`, `TestCrossOriginUploadRejectedBeforeAnyWrite`, `TestNoOriginUploadStillWorks` (`internal/api`), `TestCrossOriginUploadRefusedBeforeAnyWrite` (`internal/e2e`, real stack: no file, no row). | Clients that send neither header (curl, scripts, malware on a host that can reach the port) are allowed on purpose, so this is **not** access control. A page served from the same host:port is same-origin. Old browsers without Fetch Metadata rely on the `Origin` header, which all current browsers send on cross-origin `POST`/`DELETE`. A reverse proxy that rewrites `Host` makes browser uploads fail (see [operations.md](operations.md#cross-origin-requests-from-browsers)). Not verified in a real browser; verified with HTTP clients setting those headers. |
| **SQL injection** | All queries use bound parameters (pgx); job ids are validated as canonical UUIDs before any lookup. | |
| **Information leakage in errors** | Problem responses carry fixed messages; internal errors are logged server-side only; FFmpeg error text is sanitized of filesystem paths. | |
| **Eavesdropping on the network path** | Optional TLS 1.2+ in the application, or a reverse proxy. | Without TLS, uploads, downloads and the whole API are plaintext. The default setup is loopback-only. |
| **Database traffic and privileges** | Internal `backend` network, credentials via file secrets. api and worker connect as `convertflow_app` (`NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS`, owner of the application database only); the bootstrap superuser `convertflow_admin` password is mounted into the `db` container only. Checked by `tests/container/hardening.sh`. | The connection URL uses `sslmode=disable`; protection relies on the internal network only. A superuser role still exists inside the `db` container. Volumes created before this change keep the old superuser role until migrated ([operations.md](operations.md#upgrading-an-existing-deployment-existing-pgdata-volume)). |
| **Presigned upload forms and download URLs** (S3 storage) | A form pins the bucket, the exact key `in/<job id>`, a size of 1 byte to `CONVERTFLOW_MAX_UPLOAD_BYTES` and an expiry (`CONVERTFLOW_S3_PRESIGN_TTL`, default 15 min, at most 1 h); any extra field (ACL, content type, metadata, redirect) is refused by the store. Download URLs are valid for at most 5 minutes and carry signed `Content-Disposition`, `Content-Type` and `Cache-Control: no-store`. The API's size check at `/complete` is the authority, and the worker refuses an oversize input again. URLs and form fields are never logged or audited. Forgery attempts (another job's key, an `out/` key, extra fields, an edited or expired policy) were refused by MinIO in tests. | **A form can be reused until it expires, also after `/complete`**: S3 POST policies are not one-shot, so whoever holds the form (the uploader) can replace that job's input with another file of allowed size until expiry; ffprobe validation still applies. Anyone who obtains a form or download URL (browser history, a proxy log) can use it until it expires. Keep the TTL short. Verified on MinIO only. |
| **Object store credentials and reachability** (S3 storage) | Separate api and worker keys with least-privilege policies (`scripts/s3-bootstrap.sh` prints them; api: `in/*` write/read/delete, `out/*` read/delete; worker: `in/*` read/delete, `out/*` write/read/delete; both `s3:ListBucket`). Keys are file secrets; plain-text key variables are a start error and the config redacts them. The bucket is not public; CORS allows only the UI origin. The API's Content-Security-Policy adds exactly the store's upload origin, validated as a plain `http(s)://host[:port]`, to `connect-src` and `form-action`, and nothing else. | **TLS to the store is required outside localhost** (`CONVERTFLOW_S3_USE_SSL=true`, an `https://` public endpoint): otherwise signed requests, upload forms, download URLs and media cross the network in plaintext. The browser must reach the store, so the store is exposed to the same clients as the UI. A compromised worker can read every pending input and every retained output in the bucket (as with the shared volume). The dev/test MinIO of `compose.s3.yaml` has egress through its port-publishing network and must not be used in production. |
| **Compromised dependencies / build** | Pinned image digests, checksum-verified FFmpeg source, permissive-license policy, govulncheck, gosec, Trivy, SBOMs, signed images ([supply-chain.md](supply-chain.md)). | The pipeline has not run on GitHub yet. |
| **Data remnants after deletion** | Retention janitor, explicit delete, orphan sweep. | Plain unlink only; use an encrypted volume ([operations.md](operations.md#deletion-storage-and-encryption)). |

## What is not protected

- Confidentiality, integrity and availability against any party that can reach the port (no authentication).
- The attribution of actions to people: audit records contain the TCP peer address only, which is the proxy address behind a reverse proxy (`X-Forwarded-For` is deliberately not trusted).
- The host: the operator is responsible for the host OS, container runtime, firewall, disk encryption, backups of the database and log retention.
- Rights to the converted content and patent licensing for the `full` flavor ([licensing.md](licensing.md)).

## Hardening in the default stack

Verified by `tests/container/hardening.sh` (static compose checks plus checks of the running containers; the weakened-config self-test proves it fails on regressions): read-only root filesystems, `cap_drop: ALL`, `no-new-privileges`, no privileged mode or host namespaces, no devices, non-root users, `CapEff=0`, seccomp active, core dumps disabled, pids/memory/CPU limits, health checks, log rotation, secrets as files, API published on loopback only, internal `backend` network, digest-pinned images. With `HARDENING_PROFILE=s3` the same test covers the S3 profile (`compose.s3.yaml`), including the store container, separate store credentials and the absence of the shared volume. Note that the `api` container is also attached to the non-internal `frontend` network (needed for the published port), so it has egress capability and is not egress-isolated; the `worker` and `db` are. The api image has no shell and no media decoder, but a compromise of the API process could open outbound connections.
