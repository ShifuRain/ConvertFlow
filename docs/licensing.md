# Licensing

This document describes the licenses of ConvertFlow and of what the container images contain. **It is not legal advice.** Have your legal department review it, especially before enabling the `full` FFmpeg flavor or passing any image to a third party.

CI enforces a permissive-only policy (`scripts/check-licenses.sh`: MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, ISC; GPL, AGPL, LGPL and MPL-2.0 are rejected). The UI is plain TypeScript bundled with esbuild at build time; the build tools are not shipped. Each release ships a `THIRD-PARTY-LICENSES` directory generated by `scripts/gen-licenses.sh` (Go module license texts, per-image Debian package copyright files, `FFMPEG.txt`).

## FFmpeg is a separate program

FFmpeg and ffprobe are executed as separate processes by the worker. ConvertFlow code is not linked against FFmpeg or any codec library, so FFmpeg's license does not extend to ConvertFlow's own code. The `convertflow-api` image contains no FFmpeg at all. The `convertflow-worker` image contains the FFmpeg binaries, built unmodified from the release tarball pinned in `docker/ffmpeg.env` (currently FFmpeg 7.1.1, SHA-256 verified at build time, no patches).

## Flavors

The flavor is chosen at build time (`FFMPEG_FLAVOR`) and also set at run time (`CONVERTFLOW_FLAVOR`), where the code additionally withholds patent-encumbered encoders from the `lgpl` flavor through a fail-closed allow-list (`internal/presets/presets.go`).

### `lgpl` (default)

FFmpeg is configured without `--enable-gpl`, `--enable-nonfree` and `--enable-version3`; the image build fails if the `ffmpeg -version` configuration line contains any of them. The effective configure flags are `--disable-network --disable-autodetect --enable-zlib --enable-libsvtav1 --enable-libaom --enable-libvpx --enable-libopus --enable-libvorbis --enable-libmp3lame`. FFmpeg is then licensed under the LGPL v2.1 or later.

| Component | Used for | License (from the Debian copyright file in the image; the file lists many sub-licenses, read it for details) |
|---|---|---|
| FFmpeg 7.1.1 (libavcodec etc.) | demux, decode, filter, mux, native FLAC/PCM encoders | LGPL-2.1-or-later (this configuration) |
| SVT-AV1 (`libsvtav1enc1`) | AV1 encoding | BSD-3-Clause-Clear (AOM patent license), with some files under other permissive licenses and LGPL-2.1+ files |
| libaom (`libaom3`) | AV1 | BSD-2-Clause (AOM patent license) |
| libvpx (`libvpx7`) | VP8/VP9 encoding and decoding | BSD-3-Clause |
| libopus (`libopus0`) | Opus | BSD-3-Clause |
| libvorbis, libvorbisenc (`libvorbis0a`, `libvorbisenc2`) | Vorbis | BSD-3-Clause |
| LAME (`libmp3lame0`) | MP3 encoding | LGPL-2+ (the library; the Debian copyright file also lists some GPL-1+ files, read it) |
| zlib (`zlib1g`) | compression | Zlib |
| Debian bookworm base system | userland of the worker image | various; per-package files are under `/usr/share/doc` in the image and in `THIRD-PARTY-LICENSES/images/` |

Encoders in this flavor: libsvtav1, libvpx-vp9, libopus, libvorbis, libmp3lame, flac, pcm_s16le. The worker image carries FFmpeg's `COPYING.GPLv2`, `COPYING.GPLv3`, `COPYING.LGPLv2.1`, `COPYING.LGPLv3` and `LICENSE.md` in `/usr/share/doc/ffmpeg/`, the exact build record in `BUILDINFO` and the written source offer in `SOURCE-OFFER.txt` (also at [docker/SOURCE-OFFER.txt](../docker/SOURCE-OFFER.txt)).

LGPL points to know when you redistribute the image: provide the corresponding FFmpeg source version (named in `BUILDINFO`) and the build recipe (`Dockerfile.worker`, `docker/ffmpeg.env`), keep the license texts, and do not prevent replacing the libraries (they are dynamically linked shared libraries from Debian packages, which can be replaced). Whether a particular distribution scenario meets the LGPL is for your legal review.

### `full` (opt-in, GPL)

Adds `libx264` and `libx265` (GPL) through `--enable-gpl`, and the native AAC encoder becomes available to the presets. The resulting FFmpeg binary is licensed under the **GNU GPL v2 or later**. The configuration line of the `full` image, as built and checked for this document, is the `lgpl` line plus `--enable-gpl --enable-libx264 --enable-libx265`; check `ffmpeg -version` of your own build.

- Internal use by one organization generally does not trigger source-offer obligations. **If a `full` image is ever given to a third party** (another company, a customer, a public registry), the GPL requires offering the corresponding source of FFmpeg and the codec libraries; see the source offer below.
- The release bundles do **not** contain the `full` flavor. Build it yourself: `FFMPEG_FLAVOR=full podman compose build`. The build prints a notice; the CI job for `full` is manual-only.
- Presets only available in `full`: `video-h264`, `video-h265`, `audio-aac`.

## Patents

The `lgpl` default avoids encoders for formats covered by active patent pools. The code in this repository does not grant, and software licenses do not replace, patent licenses.

- **H.264 (AVC), H.265 (HEVC), AAC:** covered by patent pools (for example Via LA and Access Advance, among others). Using the `full` flavor can require patent licenses even for internal use, depending on jurisdiction, volume and use case. **Obtaining those licenses is the operator's responsibility.** Patent terms expire at different times in different jurisdictions. Decoding of such inputs is possible in both flavors (FFmpeg native decoders); the practical question for the operator is whether decoding or encoding in the operator's use case requires a license.
- **MP3:** the key MP3 patents have expired (the main licensor announced the end of its MP3 licensing program in 2017); this is why MP3 (LAME) is part of the default flavor. Check jurisdictional specifics.
- **AV1, VP9, Opus, Vorbis, FLAC:** designed to be royalty-free. AV1 is published by the Alliance for Open Media with a royalty-free patent license from its members for conforming implementations. That is a license grant, not a guarantee against claims of non-members (there have been public disputes about third-party patent claims against AV1 and VP9). VP9, Opus and Vorbis likewise have royalty-free grants but no absolute guarantee. This is why the default video path is AV1/VP9.

This section is a summary of the project's position, not a statement of the legal situation in your jurisdiction.

## User content

ConvertFlow does not check whether the people using it are entitled to convert the material they upload (copyright, DRM, confidentiality). That is the operator's responsibility.

## Source offer

The text of the written source offer is in [docker/SOURCE-OFFER.txt](../docker/SOURCE-OFFER.txt) and is installed in the worker image at `/usr/share/doc/ffmpeg/SOURCE-OFFER.txt`; releases also include it in `THIRD-PARTY-LICENSES/FFMPEG.txt`. In short: the FFmpeg source is the unmodified upstream release tarball named in `BUILDINFO` (https://ffmpeg.org/releases/), the build scripts are `Dockerfile.worker` and `docker/ffmpeg.env`, and the Debian library sources are obtainable with `apt-get source <package>` on a Debian bookworm system. The offer says the distributing operator provides these on request for at least three years; **an operator who redistributes images must be able to honor that offer** (keep the tarball, the build files and the package versions).
